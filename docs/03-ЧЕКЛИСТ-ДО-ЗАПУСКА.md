# Чек-лист до запуска (Pre-Launch Checklist)

Проект: Uriona · Цель: ограниченный пилот в Узбекистане · Дата: 8 октября 2026
Источники: аудит 08.10.2026 + `docs/production-business-and-tech-plan.html` (снимок 05.10.2026).

> Ключевой вывод плана остаётся в силе: **не открывать реальный checkout**, пока не выбрана модель исполнения и не проведены тестовые сделки с одним платёжным способом.

---

## A. Блокеры запуска (без них продажи НЕ открывать)

- [ ] **A1.** Покупательский запуск платежа работает: checkout → `POST /payments` → `paymentUrl` → провайдер → callback → `Payment=PAID` → `Order=PAID`. Сейчас: заказ создаётся в `AWAITING_PAYMENT`, запуска оплаты нет.
- [ ] **A2.** Выбран и подключён **один** платёжный провайдер (Click или Payme), merchant-договор подписан, боевые credentials на backend, тестовая сделка 1000 сум проведена и возвращена.
- [ ] **A3.** Модель исполнения выбрана: AliExpress DS (фактически интегрирован) или PDD API (доступа нет). Задокументировано, какие операции доступны аккаунту.
- [ ] **A4.** Подтверждена доставка: ручная схема отрепетирована (CRM-трекинг есть) ИЛИ Cainiao live-доступ получен. Cainiao не является блокером при готовой ручной схеме.
- [ ] **A5.** E2E-сценарий покупки проходит автоматически (ТЗ §47).
- [ ] **A6.** Idempotency на создании заказа (двойной клик ≠ два заказа).

## B. Инфраструктура и домен

- [ ] **B1.** DNS: дождаться, пока публичные резолверы покажут A-запись `uriona.uz → 216.24.57.1` вместо старого `176.96.243.100` (запрос в Airnet уже отправлен владельцем; записи повторно не добавлять).
- [ ] **B2.** Render: статус сертификатов `uriona.uz` и `www.uriona.uz` — сейчас `Certificate Error`; должно стать `Issued`. HTTPS домена должен отвечать.
- [ ] **B3.** API остаётся на `https://uriona-api.onrender.com`; корневой домен НЕ направлять на API.
- [ ] **B4.** Почта: платную корпоративную почту не покупать; MX/SPF/DKIM не менять наугад — только по параметрам Airnet, если понадобится.
- [ ] **B5.** Production env: `APP_ENV=production`, сильный `JWT_SECRET`, `DATABASE_URL` (managed PostgreSQL), `USD_TO_UZS_RATE`, Firebase, AliExpress (APP_KEY/SECRET/ENCRYPTION_KEY), провайдер оплаты. Проверка env при старте включена.
- [ ] **B6.** В dev-OTP `123456` нет доступа из production (`APP_ENV=production` проверяется).
- [ ] **B7.** docker-compose с healthcheck для PostgreSQL/Redis/backend; бэкапы БД настроены (ежедневно, retention 14 дней).

## C. Безопасность перед открытием

- [ ] **C1.** Репозиторий → **Private** (ТЗ §52): внутри коммерческая архитектура и внутренние DNS/IP в документах.
- [ ] **C2.** Секреты только в env/secret manager; повторный grep по истории git (`*.key`, `*.pem`, `token`, `secret`).
- [ ] **C3.** Rate limiting: глобальный + auth endpoints (OTP cooldown и лимиты — уже есть после аудита).
- [ ] **C4.** Security headers (helmet), CORS — точный список доменов (wildcard `*.onrender.com` убран в аудите).
- [ ] **C5.** Платёжные callback: подпись + merchant + сумма + заказ + транзакция + дубликат — по каждому провайдеру тест «неверная подпись отклонена».
- [ ] **C6.** Frontend не хранит секретов; токен сессии — в localStorage как допущено для MVP, план перехода на HttpOnly cookie зафиксирован.

## D. Продукт и контент

- [ ] **D1.** Все кнопки работают (чек-лист 18 кнопок, ТЗ §38); нет «декоративных» элементов.
- [ ] **D2.** Ошибки показываются понятно; «API не работает» заменено на конкретные сообщения (`Pinduoduo API пока не настроен` и т.п.).
- [ ] **D3.** Источник товара маркирован (локальный / marketplace); нет смешения без маркировки.
- [ ] **D4.** Изображения товаров реальные или placeholder — нет сломанных `<img>`.
- [ ] **D5.** Цены в UZS от backend; нет сложения CNY+UZS; нет float в деньгах.
- [ ] **D6.** В UI нет заявлений о партнёрстве с Uzum/Cainiao, пока интеграции нет.
- [ ] **D7.** Мобильная вёрстка проверена на 375–430px; Android-приложение остаётся прототипом и не блокирует веб-запуск.

## E. Операционная готовность

- [ ] **E1.** CRM: статусы заказов, трекинг, финансы — проверены администратором; доступ только по роли ADMIN.
- [ ] **E2.** Сценарий возврата/отмены отрепетирован: refund через провайдера, `Order=CANCELLED/REFUNDED`, финансовая запись.
- [ ] **E3.** Мониторинг: health endpoint `/api/v1/health` подключён к uptime-проверке; логи с requestId доступны.
- [ ] **E4.** Контакты поддержки на сайте рабочие (Telegram/телефон), страница `/support` заполнена.
- [ ] **E5.** Пилот: 5–10 реальных заказов знакомых покупателей, полный цикл включая доставку и (если нужно) возврат.

## F. Порядок открытия продаж

```text
A1–A6 закрыты
→ B1–B7 подтверждены (домен открывается по HTTPS)
→ C1–C6 пройдены
→ D1–D7, E1–E4 проверены
→ E5: пилотные заказы успешны
→ Открыть checkout всем покупателям
```

Текущий статус: **держать checkout закрытым** — пункты A1, A2, A5, A6 не выполнены.
